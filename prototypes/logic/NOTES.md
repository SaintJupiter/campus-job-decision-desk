# 原型结论

## 正在验证

- Campaign 是否被可靠隔离；
- 具体官方岗位是否能正确晋升为 Posting；
- 字段级官方证据是否只覆盖自己明确声明的字段；
- 去重是否优先避免错误合并；
- Eligibility 是否在关键信息缺失时保持 UNKNOWN；
- 页面无法访问是否保持 UNKNOWN，而非 CLOSED。

## 待填写

运行原型后记录：

1. 哪个状态或动作不自然；
2. 哪个字段仍无法表示；
3. 哪些规则可直接吸收到正式数据层；
4. 哪些功能应继续由人工完成。

## 第一次自动演示发现

1. 去重结论为 `SEPARATE` 或 `REVIEW` 时，不能继续把候选记录聚合成一个虚构岗位计算三轴；已改为停止计算并要求分别创建 Posting 或人工确认。
2. 相同官方岗位 ID 可以确认记录属于同一 Posting，但公司法定名称和展示名称、标题空格与括号仍可能不同；需由官方具体职位 Claim 选定显示值，同时保留原始变体。
3. Campaign、官网未声明毕业窗口、官网 `NOT_FOUND` 三类场景均需要把未知显式保留下来，不能默认可投或关闭。
