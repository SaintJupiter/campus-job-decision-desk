# 隐私、版权与数据边界

## 数据分类

| 数据 | 存储与公开策略 |
| --- | --- |
| 付费校招表原文 | 仅本地 `data/private/`，Git 忽略，不进入公开截图、测试或报告 |
| 完整个人简历 | 仅本地数据库；可一键删除事实、偏好和派生决策 |
| 官网证据 | 保存 URL、核验时间、短摘录和字段；不镜像整站 |
| 合成演示数据 | 可提交，用于演示完整工作流；公司、岗位和域名均为虚构 |
| 私有数据统计 | 仅发布聚合数量与比例，不发布可还原单条岗位的切片 |

## 产品级保护

- `make demo-db` 只删除并重建精确的 `data/demo/public-demo.sqlite{,-wal,-shm}`；不在旧库上补写“合成数据”标记。
- `public-demo` 只接受精确的 `data/demo/public-demo.sqlite`；启动前先拒绝其他路径，不执行建表、迁移或决策刷新。
- 合成来源和一次性工作区标记之外，启动还会重算除元数据表外的全库 SHA-256 内容封签；任何后续简历、偏好、岗位或决策写入都会使公开演示拒绝启动。
- 通过全部校验后，`public-demo` 的写请求仍统一返回 403。
- 前端无法读取运行模式时默认只读，避免“确认失败后放开写入”。
- 原始行和批次由 SQLite 触发器保护，应用层不能修改或删除。
- SPA 静态文件路由执行路径解析与目录 containment，不能访问构建目录之外的文件。
- 短名单导出再次执行资格、官网、证据新鲜度与状态门禁，不信任旧界面状态。
- 所有外链保留原始来源或已确认官网标记，聚合链接不会显示成“官网”。

## 使用者责任

- 导入前确认自己有权使用岗位表；系统不提供付费数据转售或再分发能力。
- 对外展示仅使用 `data/demo/` 与派生统计。
- 最终投递前仍需在企业官网确认岗位、截止时间和资格；“页面开放”也不等于企业仍有实际 headcount。
- 若接入外部大模型，必须在调用前明确脱敏和用户同意；当前默认实现不依赖外部模型 API。

## 删除语义

“删除证据画像”会删除简历事实、用户偏好、关联的旧决策与画像事件；不会删除岗位表的原始批次。这样既满足个人数据撤回，也保留岗位数据血缘。
