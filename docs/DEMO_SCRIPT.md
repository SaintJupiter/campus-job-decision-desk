# 三分钟演示脚本

## 0:00–0:25｜问题

打开“数据来源”。说明同一份国内校招聚合表中，约半数行是多个岗位或宽泛岗位族，四成左右包含多个城市；把一行直接送给大模型打匹配分，本身就没有稳定语义。

## 0:25–0:55｜导入与粒度

选择一份合成岗位表，先执行“预览解析”。展示：

- 原始行数、成功和失败行；
- `Campaign` 与 `Posting` 数量；
- 文件指纹、字段映射和每行分类依据；
- 只有确认后才形成不可变批次。

切到“核验工作台”，展示一条“多岗位 × 多城市”的招聘活动被隔离为 `Campaign`，没有被自动展开成虚假岗位。

## 0:55–1:35｜字段证据与身份

打开“AI 产品经理”具体岗位：

- 两个供应商原始行仍分别存在；
- 公司、岗位、城市、届次、截止时间等字段各自保留来源说法；
- 官网只覆盖页面明确声明的字段；
- `NOT_FOUND` 不会被写成 `CLOSED`。

指出官方域名和岗位 ID 需要显式确认，招聘首页不能核验成具体岗位。

## 1:35–2:10｜证据画像与三轴

打开“我的证据画像”：规则抽取候选、简历原文和用户确认分层。回到岗位详情，说明：

- 可投性只看硬条件；
- 经历证据引用简历原句，不生成“你具备 8.7 分推动力”；
- 信息可信度单独显示官网、冲突和时效。

故意修改城市偏好，展示旧决策立即失效并要求重算。

## 2:10–2:40｜可信投递计划

展示国内校招筛选维度和临近截止排序，再进入可信投递计划，查看岗位当前阶段、下一步行动与计划日期。强调只有官网状态和硬条件通过的具体岗位才能进入可导出队列。

尝试加入一条未核验或证据过期的岗位，服务端拒绝。加入已通过门禁的岗位后，导出 CSV / JSON；导出链接是当前已核验具体岗位，不是聚合表首页。

## 2:40–3:00｜结果与边界

打开评测报告，展示分类契约集、消歧契约集、守卫测试、私有快照汇总和 API 基准。明确说明：

- 合成契约集证明边界规则可复现，不等同于真实世界模型准确率；
- 目前没有声称提升面试率或 Offer 率；
- 下一步是真实 3–5 人的“15 分钟找 5 个可信岗位”任务测试。
