# 界面信息架构：松弛外壳，高密度工作区

> 2026-08-10。该文档约束正式前端，不是单独的视觉稿。

## 核心原则

1. **颜色只标记任务和状态，不承担页面分区。** 每个页面最多一个大面积主色域；其余使用暖白背景、细分隔线和局部状态色。
2. **概览低密度，工作区高密度。** 页头负责方向，列表/表格负责比较，详情负责追溯；同一信息不在三处重复。
3. **一屏一个主动作。** “今天去投”“补官网证据”“导入来源”等主动作必须比次要管理操作更明显。
4. **默认显示决策所需最小信息，证据按需展开。** 列表展示资格、匹配证据、可信度和最大阻断项；完整 Claim、RawRecord 与历史只在详情中出现。
5. **密度来自对齐，不来自缩小字号。** 表格化行布局、稳定列宽、紧凑状态标签和留白分组并用，正文不低于 12px。

## 成熟产品中借鉴的模式

- [Huntr](https://help.huntr.co/en/articles/13413245-the-job-board)：主工作区直接围绕岗位状态和下一步动作组织，不让统计抢走主要空间。
- [Teal](https://join.tealhq.com/)：跨来源保存岗位后，围绕岗位、简历和行动形成持续工作流。
- [Linear](https://linear.app/now/behind-the-latest-design-refresh)：位置栏、视图控制和内容层级保持一致，弱化非激活导航并增加纵向间距。
- [Clay](https://www.clay.com/)：大量异构字段进入紧凑表格，颜色只强调状态、选择和异常。
- [Attio](https://attio.com/)：记录列表与记录详情分层；时间线、属性和操作在详情页渐进披露。

## 各页面必须回答的问题

### 1. 今日决策

**用户问题：今天先做什么，哪些岗位最值得立刻行动？**

- 常驻：可信投递目标、已确认数量、待核验数量、字段冲突数量。
- 主列表：最多 4 个“可直接投”，展示公司/岗位、城市届次、三轴、官网状态和投递入口。
- 次列表：最多 4 个“补一项信息就可能可投”，突出唯一阻断项和建议动作。
- 不展示：全量来源质量、完整评测指标、长篇产品说明。

### 2. 岗位池

**用户问题：我有哪些机会，如何快速缩小范围？**

- 顶部工具栏：搜索、Campaign/Posting、城市、届次、资格、可信度、冲突状态；已选条件可见且可一键清空。
- 主体采用高密度行：岗位与公司 / 城市届次 / 三轴 / 来源与更新时间 / 下一步动作。
- Campaign 与 Posting 视觉分流；Campaign 的动作是“找具体岗位”，Posting 的动作是“看证据/投递”。
- 不用瀑布流大卡片，不在列表展开完整未知项和历史。

### 3. 岗位详情

**用户问题：为什么系统得出这个结论，我现在要做什么？**

- 首屏：公司岗位、当前分类、三轴结论、官网状态、唯一主动作。
- 决策区：Eligibility / Evidence Fit / Trust 三列，每列显示结论、最多 3 条理由、未知项和引用证据。
- 证据区：字段 Claim 矩阵，当前采用值与历史/不适用证据明确区分。
- 工作区：官网核验、官方身份、Campaign→Posting 关联、人工判断。
- 深层信息：核验历史、原始来源行、事件记录使用折叠面板。

### 4. 核验工作台

**用户问题：处理哪条信息最可能改变投递结果？**

- 队列按“决策影响”而不是更新时间排序。
- 每行必须出现：阻断原因、缺失字段、当前来源、最近核验、建议动作。
- 重复候选与岗位核验是两种任务，使用明确分区，不混在同一列表中。
- 系统边界说明缩成一条提示，不占据主工作区。

### 5. 数据来源

**用户问题：数据从哪来、今天是否更新成功、这次导入会发生什么？**

- 连接区：本地文件、飞书多维表格 URL，两种入口并列但不混成一个表单。
- 来源列表：来源类型、独立组、最近成功同步、记录数、失败/过期状态、下一次动作。
- 导入必须保留 preview→confirm；预览突出新增、修改、缺失、Campaign/Posting 和失败行。
- 批次历史默认紧凑表格，错误明细按需展开。

### 6. 可信投递计划

- 只允许满足服务端门禁的具体岗位进入；
- 显示待投递、已投递、笔试/测评、面试与 Offer 阶段；
- 每条记录维护下一步行动与计划日期，状态失效时仍展示阻断原因。

**用户问题：哪些岗位今天真的能投，哪些曾经入选但现在被阻断？**

- Ready 与 Blocked 分组；默认先显示 Ready。
- 每行展示优先级、三轴、官网入口、加入时间和阻断原因。
- 导出操作与“当前可导出数量”绑定，避免导出按钮看似可用却没有有效记录。

### 7. 效果证据

**用户问题：这个项目真正证明了什么，还不能证明什么？**

- 第一屏先显示边界结论，不把测试通过包装成求职效果。
- 指标按“安全边界 / 数据结构 / 性能 / 用户验证”四组组织。
- 评测表格保持高密度；下一步真实用户测试单独展示。

### 8. 我的证据画像

**用户问题：系统引用了我的哪些事实，哪些只是偏好或待确认候选？**

- 上传与粘贴是入口；已确认事实、抽取候选、偏好分组显示。
- 每项事实始终能回到简历原文 span。
- 修改参与计算的事实时，清楚提示哪些岗位决策会失效。

## 密度与视觉规则

- 桌面内容宽度：`1240–1360px`；外侧保留背景边界。
- 页面区块间距：`36–48px`；同一工作区内部：`12–20px`。
- 列表行高：`84–112px`，复杂详情可到 `128px`；禁止每条岗位都变成 220px 大卡片。
- 大色域：今日任务淡紫；待处理任务淡黄；可信证据淡绿；引用证据淡蓝。
- 状态色只使用在文字、圆点、标签和选中行，不给所有容器染色。
- 阴影只用于浮层和首要概览；工作区使用 1px 分隔线。
