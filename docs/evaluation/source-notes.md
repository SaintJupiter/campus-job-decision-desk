# 评测报告来源与可视化说明

## 报告脊柱

1. 回答“现在能证明什么、不能证明什么”。
2. 展示可复现契约与数据结构质量，而非虚构推荐准确率。
3. 将真实用户任务测试列为下一阶段，不把待验证内容写成已完成结果。

## 来源

- `evaluation/results/latest.json`：评测器输出的聚合结果。私有数据库经过 SQLite backup 只读复制，迁移与分析只发生在临时副本。
- `evaluation/fixtures/gold.json`：开发者编写的合成输入和预期，可逐条审阅。
- `scripts/run_evaluation.py`：生成上述聚合结果的复现入口。

## 图表映射

- `quality-gates`：横向条形图；类别为门槛，数值为各自分母内的通过/覆盖率。数据集同时保留分子、分母、证据类型和解释，方便审计。
- 未制作趋势图：只有一次评测快照，没有时间序列，画趋势会误导。
- 未制作供应商准确率图：当前没有完整人工 Gold 标注，也没有足以代表供应商总体质量的抽样框。
- 未制作面试率/录用率图：项目尚无足够周期、样本和可归因对照。

## 指标边界

- Contract 通过率只衡量声明的安全不变量是否回归。
- Heuristic exact match 只衡量 8 条开发者合成样本。
- 数据库覆盖率只衡量结构连接，不衡量每条岗位语义正确性。
- API 延迟只是在本机同进程 TestClient 上的观测，不是生产 SLO。
